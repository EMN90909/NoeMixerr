NoeMixerr v0.4.0 (development milestone)
=======================================

NoeMixerr is a C++/Qt digital audio workstation derived from LMMS.
This source tree is intended for development and testing. Native CI artifacts
are NOT complete, signed installers.

For the maintained platform-specific prerequisites and troubleshooting guide:
  BUILDING.md
  https://github.com/EMN90909/NoeMixerr/blob/main/BUILDING.md

Use a recursive checkout because some synthesizers and plugins use submodules:
  git clone --recurse-submodules https://github.com/EMN90909/NoeMixerr.git
  cd NoeMixerr

A portable baseline development build (run in a shell with prerequisites):
  cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON -DWANT_SWH=OFF
  cmake --build build --parallel 2
  ctest --test-dir build --output-on-failure
  python3 tools/check_version.py build/noemixerr
  python3 tools/test_project_compatibility.py build/noemixerr
  python3 tools/test_audio_render.py build/noemixerr

On Windows, use the MSYS2 UCRT64 terminal and its packages, not a bare
PowerShell shell. See BUILDING.md for the supported setup.
The final executable is usually build/noemixerr (or build/noemixerr.exe).
Ensure all required dynamic libraries, Qt platform plugins, application
resources and synth plugins are installed before treating a build as portable.

To stage installation after a successful build:
  cmake --install build --prefix /absolute/destination
Use a writable destination. System installation is not required for testing.

To launch the editor:
  ./build/noemixerr
On Windows (MSYS2 UCRT64):
  ./build/noemixerr.exe

Tests of hardware audio playback, microphone recording, MIDI devices and
third-party plugin loading must be performed on physical target systems.
Passing CI or headless rendering alone does not establish audio-device support.
